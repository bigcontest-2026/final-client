# HERMES durable report job client evidence

## Scope and defaults

Summary, investigation and assistance use the exact `report-job-1` API in the design. Legacy synchronous API functions remain compatible for existing consumers. A view owns one abortable observation controller. Polling defaults to 2 seconds, a 10-minute observation budget (including an in-flight status request), and at most 5 consecutive transient failures. Backoff doubles up to 30 seconds and honors numeric `Retry-After`. A polling limit pauses observation; it does not cancel a server job. A user can resume observation or explicitly cancel it.

Job identity, report ID, kind and schema are checked before state updates. Late responses after abort/dispose are ignored. A child investigation is allowed to attach to its original root, matching existing server behavior. Assistance always previews the proposal and requires an explicit application; exact submitted draft and report fingerprints are checked again at application. A restored proposal without matching browser-local request context is read-only.

## Reproduce

From `frontend`:

```sh
npm test
npm run typecheck
npm run build
npm test -- --run src/lib/jobs/lifecycleTrace.test.ts
```

Dependencies were copied from the authorized read-only existing checkout rather than installed into or changed in that original checkout.

Baseline: 53 tests across 9 files, typechecked production build passed. After: 74 tests across 15 files, typecheck and production build passed. Both baseline and after builds show Vite's existing >500 kB bundle-size advisory. Baseline JS was 576.55 kB, after JS 583.87 kB (gzip 181.53 → 183.82 kB; tool output, not a runtime benchmark).

Lifecycle tests cover 202 acknowledgement followed by success, failed/retry, explicit cancel and late-result fencing, view-close observation cleanup without server cancellation, transient failures and Retry-After, bounded failure/elapsed/in-flight waits, list-based restoration, per-job context restoration, report/job identity mismatch, edited assist draft protection, unknown restored proposals, and child→root investigation attachment.

## Synthetic timing fixture

`durable-report-job-trace.json` is generated by the real legacy summary helper and new controller against deterministic mocked HTTP with a Vitest virtual clock. Eight samples, completion durations 600/1800/2600/4200 ms repeated twice, 5 ms fixed HTTP envelope, 1000 ms polling, 10000 ms observation budget. Production defaults are listed above; the trace deliberately uses an explicit shorter test interval.

| Measurement (virtual ms) | p50 | p95 |
|---|---:|---:|
| Legacy request-bound first feedback | 1805 | 4205 |
| Durable queued acknowledgement | 5 | 5 |
| Durable terminal observation | 2015 | 5030 |

All 8 final summaries match their source report; zero failed samples. The complete request/poll/status sequence for each sample is in JSON. This demonstrates early acknowledgement and polling detection delay only. It is not a real LLM latency, GPU throughput, deployment, or provider correctness measurement.

## Browser fixture and verification limit

`frontend/tests/job-lifecycle.html` and `job-lifecycle.tsx` render the actual report/assist components against an entirely in-browser deterministic API. They never call a real provider/server and are not an entry point in the production build. Start Vite on a free dedicated local port, for example:

```sh
npm run dev -- --host 127.0.0.1 --port 5192 --strictPort
```

Open `/tests/job-lifecycle.html`. Three 2-second polls reach success. Controls allow closing/reopening the views, failing the next request, and resetting only this fixture's storage. Test reload restore, explicit cancel/retry, child re-investigation, identical-payload reuse, and edit the visible draft name while assist runs to verify the original draft is preserved and application is disabled. The fixture module was separately typechecked.

In the implementation sandbox, starting Vite failed with `listen EPERM: operation not permitted 127.0.0.1:5192`. No listener was created. Visual browser confirmation remains unverified. The parent separately verified the actual TypeScript client/controller against FastAPI TestClient through stdio IPC using a 50 ms mock provider; see `hermes-ipc-integration.md` and the accompanying JSON. This was not a browser or real-provider check. No external model call or deployment was performed.
